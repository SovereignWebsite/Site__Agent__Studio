Debrief: "The Last Boring Slide", how a cinematic WebGL deck is wired

This folder is a reverse-engineering debrief of the artifact The Last Boring Slide (Copy): a 13-scene talk rendered entirely in real time with WebGL 2 / three.js, with procedural audio, speaker notes and a presenter UI, shipped as one self-contained HTML file (~7,000 physical lines, several MB).

It is written for an agent (or engineer) who has to build decks of the same kind. Read in order:

TL;DR

  • Stack: three.js r187 (used mostly as a WebGL2 state manager, nearly every material is a raw GLSL3 ShaderMaterial), hand-written GLSL, Canvas2D for glyph rasterisation, WebAudio for sound. No other runtime libraries. No images, video or audio files: everything is generated at load time.
  • Engine: a small custom presentation runtime (createDeck) that owns the render loop, a scene contract (create → {init, enter, exit, update, render, pointer, resize}), timed beats inside each scene, and transitions that composite two scene render targets.
  • Look: each scene renders HDR into its own targets, then a shared post pass (6-level bloom, AgX or ACES tonemap, contrast/saturation, vignette, grain) and a final dithered present.
  • Authoring style: procedural everything, terrain from noise functions, trees from recursive tube geometry, clouds raymarched through a 3D noise texture, sounds synthesised sample-by-sample.
  • Packaging: source was clearly a multi-module ES project, bundled + minified (esbuild-style IIFE), with three.js and base64 fonts inlined so the result is a single file publishable as an artifact.

Provenance / licensing notes (not legal advice)

  • three.js is MIT-licensed (its notice is preserved at the top of the script).
  • Fonts embedded: Geist, Geist Mono, Newsreader, Unbounded ("Unb"), Anton, JetBrains Mono, all published under the SIL Open Font License. A font named "Pixel" is also loaded; its origin is not identifiable from the file, so check before reusing it.
  • Everything else, engine, shaders, scenes, audio, is original code by the deck's author. There is no proprietary dependency, but there is also no licence attached to that code. The techniques are standard and free to reuse; copying the code verbatim is a question for its author.

What was read

The debrief is based on reading the application code directly: the boot/engine section (utilities, GLSL libraries, gfx, post stack, fonts, text system, view, overlays, SelectBox, createDeck, presenter UI, boot), the complete audio engine, the "office" opener, the "futures" landscape, the "pile" recap, the "questions" closer, and the slam / daybreak / line / tear transitions. The bundled three.js (~5,200 lines) was skipped. The middle scenes (tower, boat, loop, swarm, dominoes, calendar, lamp, selectall, aim) were only sampled, so the catalogue for those is inferred from names, audio beds and fragments and is marked as such.
