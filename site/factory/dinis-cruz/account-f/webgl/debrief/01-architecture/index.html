01: Architecture

The file

<!doctype html>
<head>  host boilerplate (viewport, safe-area padding, base font)
<body>
  <title>The Last Boring Slide</title>
  <style>   ~25 lines: #stage canvas full-window, #ui overlay, .notes, .over (grid), .help, .toast, .load
  <canvas id="stage" tabindex="0">
  <div id="ui"></div>
  <script>
     /* three.js MIT header */
     window.__FONTS = { "GeistMono-latin.woff2": "data:font/woff2;base64,…", … }   // all fonts inlined
     (()=>{                                    // one IIFE = bundler output
        …three.js r187 (minified, ~5,200 lines)…
        …app: utils → GLSL libs → gfx → fonts → text → view → overlay → SelectBox
              → createDeck → presenter UI → boot(C3) → transitions → audio → scenes …
        C3({ createDeck, scenes:[13], transitions:{10}, makeAudio, headless })
     })();
  </script>

Everything is inside the one <script>. Optional external hooks exist but are unused in the published file: window.__ASSETS[name] (falls back to assets/<name>), fonts/<file> fallback when __FONTS lacks an entry, and thumb-<sceneId>.jpg for the overview grid.

Boot sequence

  1. C3(...) → createDeck({canvas, scenes, transitions, headless, qs, makeAudio}).
  2. createDeck awaits loadFonts() (FontFace from __FONTS data URIs), creates gfx, view, the text system, audio, the shared context object ctx, three scratch targets, and wraps each scene definition in a SceneRunner.
  3. If WebGL 2 fails → a help box: "This presentation needs WebGL 2…".
  4. Unless ?quick or headless: show "Opening presentation" + progress bar and run deck.warmAll(progress), every scene is init-ed, every beat rendered once at p=0.5 and 1, and its entry transition rendered at p = .2/.5/.8 into scratch targets. This compiles all shaders and allocates all targets before the talk starts, so there are no hitches mid-presentation.
  5. Start at the scene/beat from location.hash (#futures-2), else the first scene.
  6. Attach presenter UI; set window.ready = true (a hook for headless capture tools).

How the single file was most likely produced

The code shape says: ES modules + three.js imported from npm → bundled and minified (mangled two-letter names, var X=class{…}, one IIFE, __FONTS/__ASSETS globals for inlined resources) → a post-build step that base64-inlines fonts (and would inline assets) and writes one HTML file. ?headless, window.__fdiv, window.ready and deck.test.{seek,trans,perf} exist so an automated browser can render any scene/beat/transition frame deterministically, which is how the author verified the visuals and generated thumbnails. See 09-playbook-for-agents.md for a reproduction of that pipeline.
